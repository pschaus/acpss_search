    \section{TinyCSP has lost its search}

    In this exercise, we will study a simple CSP solver in Java called TinyCSP.
    Let us first see how to model the NQueens problem using TinyCSP.
    The NQueens problem is to place N queens on an $N \times N$ chessboard such that no two queens threaten each other.
    The model is given in the code Listing~\ref{nqueen}.

    \begin{minipage}{\linewidth}
        \lstinputlisting[language=Java, label=nqueen, caption={NQueens Model using TinyCSP}, escapeinside={(*@}{@*)}]{figures/NQueens.java}
    \end{minipage}

    The domain to represent the values of the variables is implemented in the class \texttt{Domain}
    in Listing~\ref{domain}.
    It is a simple implementation of a domain using a \texttt{BitSet} to represent the set of values.


    \begin{minipage}{\linewidth}
        \lstinputlisting[language=Java,label=domain, caption={Domain Implementation in TinyCSP}, escapeinside={(*@}{@*)}]{figures/Domain.java}
    \end{minipage}



    The variable implementatino is very simple in Listing~\ref{variable}, it just contains a domain.

    \begin{minipage}{\linewidth}
        \lstinputlisting[language=Java,label=variable,caption={Variable Implementation in TinyCSP}, escapeinside={(*@}{@*)}]{figures/Variable.java}
    \end{minipage}


    The constraint implementation is given in Listing~\ref{constraint}.
    A \texttt{Constraint} is an abstract class with an absract method \texttt{propagate()}
    that is called by the solver to remove inconsistent values from the domains of the variables involved in the constraint.
    It also returns true if any value could be removed from the domains of the variables involved in the constraint.
    The constraint can also throw an \texttt{Inconsistency} exception if the constraint is not satisfiable.

    In \texttt{TinyCSP}, we have only one constraint implemented, the \texttt{NotEqual} constraint.
    Of course feel free to implement more constraints during your free times.

    \begin{minipage}{\linewidth}
        \lstinputlisting[language=Java,label=constraint,caption={Constraints Implementation in TinyCSP}, escapeinside={(*@}{@*)}]{figures/Constraint.java}
    \end{minipage}


    The \texttt{TinyCSP} solver class is given in Listing~\ref{tinycsp}.
    It contains a list of constraints and a list of variables.
    The solver provides factory methods to create variables, add constraints, and trigger fix point propagation.
    Unfortunately, the search is not implemented yet.

    \begin{exercise}
        Select all variable selection heuristics that are \textbf{not} in the spirit of the first-fail principle:
        \begin{enumerate}
            \item Select an unfixed variable with the largest domain size.
            \item Select a random unfixed variable.
            \item Select an unfixed variable with the smallest domain size.
            \item Select an unfixed variable involved in the largest number of constraints.
            \item Select an unfixed variable having the lowest propagation activity.
            \item Select an unfixed variable involved in the smallest number of constraints.
            \item Select a value that has the smallest lower-bound propagation impact.
        \end{enumerate}

    \begin{exercise}
        Consider seven variables $X, Y, Z, A, B, C, D$ such that:

        \begin{itemize}
        \item $X, Y, Z$ have the domain $\{0,1\}$ and there are no constraints on these variables.
        \item $A, B, C, D$ have the domain $\{0,1,2\}$ and there is a single constraint: $AllDifferent(A, B, C, D)$ implemented using forward checking (only fixed variables are removed from the domains of the other unfixed variables).
        \end{itemize}
        Consider a \emph{conflict-ordering search} that, by default,
        considers the variables in the order given above $X \leftarrow  Y \leftarrow  Z \leftarrow  A \leftarrow  B \ldots $ and always tries,
        given a selected variable $V$, $V = V.min()$ on the left branch, and $V \neq V.min()$ on the right branch.

        There are no solutions to this problem.
        Draw the search tree.
        How many nodes are visited during the search?
    \end{exercise}

    \begin{exercise}

        In this model, there is a constraint $C$ that acts on some variables.
        Two propagators are available for this constraint $C$.
        The first propagator ensures bound consistency and the second domain consistency.

        Strangely, fewer backtracks are observed with the weaker propagator than with the stronger propagator.
        Assuming there are no bugs, how can this be explained?

    \section{Value Heuristics}


    \begin{exercise}
        Consider the Traveling Salesman Problem (TSP) with 6 cities represented by the circuit shown in Figure~\ref{fig:tsp_heuristic}.
        Compare the three heuristics $H_1$, $H_2$, and $H_3$ for selecting the next variable to branch on and the value for the leftmost branch.
        Depict the circuit obtained when reaching the first left-most solution by each heuristic in Figure~\ref{fig:tsp_heuristic}.
        \begin{enumerate}
            \item $H_1$. Static Variable Heuristic. Assign the variables in the order $X_A \rightarrow X_B \rightarrow X_C \rightarrow \ldots \rightarrow X_F $.
            Choose as value for the leftmost branch the closest successor.
            \item $H_2$. Choose as next variable, the one that corresponds to the last assigned value (end of partial circuit).
            Choose as value for the leftmost branch the closest successor.
            \item $H_3$. Min Regret Variable Heuristic. For each unassigned position $X_i$, calculate the \emph{regret} for each successor.
            The regret of of $X_i = d_{i,v_a} -d_{i,v_b}$ where $d_{i,v_a}$ is the minimum distance from position $X_i$ a possible position
            and $d_{i,v_b}$ is the second minimum distance from position $X_i$  to a possible position.
            Choose as value for the leftmost branch the closest successor.
        \end{enumerate}
        \label{ex:val_heuris2}
    \end{exercise}

    \begin{exercise}
        Select all the true statements regarding value selection heuristics:
        \begin{enumerate}
            \item Once the variable to branch on has been selected, it is important to select as value for the leftmost branch one that has the highest chance to lead to failure, in the spirit of the first-fail principle. %F
            \item Once the variable to branch on has been selected, it is important to select as value for the leftmost branch one that has the highest chance to lead to success. %T
            \item The value selection heuristic should mimic a greedy algorithm to find good solutions early. %T
            \item Phase saving is a learning scheme for the value selection heuristic that tries first the last value that was tried without failing. %T
            \item Selecting a value that has the least impact on the objective bound should lead to a good first solution. %T
            \item The value selection heuristic is not important for satisfaction problems. %F
        \end{enumerate}
        \label{ex:value_heuristics}
    \end{exercise}
